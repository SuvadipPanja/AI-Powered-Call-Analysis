## Single `.env` template

Copy `production/.env.example` → `.env` on prod. Required keys include:

- `PUBLIC_HOST`, `SA_PASSWORD`, `HOST_MAC`, `CORS_ORIGIN`
- `LICENSE_SECRET_KEY` (exactly 32 chars), `ORCHESTRATOR_SECRET`, `CALLBACK_SECRET`, `SERVICE_TOKEN`
- `LICENSE_PUBLIC_KEY_PATH=/app/keys/vendor-root-public.pem`

After editing `.env`:

```bash
bash scripts/bootstrap-prod-secrets.sh
```

This writes `secrets/*` and regenerates `.env.container`. Recreate backend after secret changes:

```bash
docker compose up -d --force-recreate --no-deps backend
```

---

## `.env.container` (auto-generated)

Bootstrap copies `.env` → `.env.container` and **removes** these keys so they never appear in `docker exec … printenv`:

- `LICENSE_SECRET_KEY`, `ORCHESTRATOR_SECRET`, `CALLBACK_SECRET`, `SERVICE_TOKEN`
- `SA_PASSWORD`, `DB_PASSWORD`

The backend loads those values from `/run/secrets/*` instead. Non-secret config (`LICENSE_PUBLIC_KEY_PATH`, `CORS_ORIGIN`, queue flags, etc.) stays in `.env.container`.

**Do not edit `.env.container` manually** — always edit `.env` and re-run bootstrap.

If prod still has `.env.secrets` and/or `.env.backend` from an old workflow:

1. Merge secret lines into `.env` (one line per key; no duplicates).
2. Set `LICENSE_PUBLIC_KEY_PATH=/app/keys/vendor-root-public.pem`.
3. Remove or rename `.env.secrets`, `.env.backend`.
4. Run `bash scripts/bootstrap-prod-secrets.sh` and recreate backend.

Backend `env_file` in `docker-compose.yml` must be `.env.container` (generated from `.env`).
